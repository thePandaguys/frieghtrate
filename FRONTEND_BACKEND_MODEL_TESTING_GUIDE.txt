FREYNA FREIGHT FORECASTING
FRONTEND + BACKEND + ML MODEL TESTING GUIDE
============================================================

Purpose
-------
Use this guide to test the project in layers:

1. Python environment and ML model loading
2. FastAPI backend health and prediction endpoints
3. Expo frontend startup and browser/device connection
4. Frontend -> backend -> model end-to-end flow

Run PowerShell commands exactly as shown. Open separate PowerShell terminals for
long-running backend and frontend processes.

REQUIREMENTS
------------
Install or verify these before testing:

- Windows PowerShell
- Python 3.11+ recommended
- Node.js and npm
- PostgreSQL running locally or a reachable PostgreSQL server
- PostgreSQL database matching DATABASE_URL in backend/.env
- Android Studio emulator, Expo Go, or a web browser for frontend testing

The backend API can answer /api/health without a database, but prediction
endpoints save history and therefore require a working PostgreSQL database.

IMPORTANT CONFIGURATION NOTE:
backend/.env.example uses database name freight_forecasting, while the checked-in
backend/alembic.ini references freight_intelligence. Set DATABASE_URL in
backend/.env to the database you actually create. The .env value is authoritative.

STEP 3 - VERIFY THE THREE MODEL FILES
--------------------------------------

Run this from the project root. It checks that every expected file exists and
that the backend model registry can load it with the installed dependencies:

    .\.venv\Scripts\python.exe -c "from pathlib import Path; from backend.app.ml import ModelRegistry; root=Path('models'); expected=['freight_forecasting_model.pkl','vessel_idle_prediction_model.pkl','freight_risk_model.pkl']; print({name:(root/name).exists() for name in expected}); registry=ModelRegistry(); registry.load_all(); print('LOADED:', sorted(registry.models)); print('ERRORS:', registry.errors)"

Expected result:
- all three file checks are True
- LOADED contains forecast, risk, and vessel
- ERRORS is {}

If the import command fails because of package resolution, run it from backend:

    Set-Location .\backend
    ..\.venv\Scripts\python.exe -c "from app.ml import ModelRegistry; registry=ModelRegistry(); registry.load_all(); print('LOADED:', sorted(registry.models)); print('ERRORS:', registry.errors)"
    Set-Location ..

Do not continue until model loading succeeds. A model loading error usually means
an incorrect model file, missing dependency, or incompatible scikit-learn/XGBoost
version.


STEP 4 - CONFIGURE BACKEND ENVIRONMENT
--------------------------------------

Create backend/.env from the example:

    Copy-Item .\backend\.env.example .\backend\.env -Force
    Get-Content .\backend\.env

Make sure DATABASE_URL points to a real PostgreSQL database. Example:

    DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/freight_forecasting
    ENVIRONMENT=development
    CORS_ORIGINS=http://localhost:8081,http://localhost:19006,http://localhost:3000
    MODEL_DIRECTORY=../models

If your database is named freight_intelligence instead, use:

    DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/freight_intelligence


STEP 5 - CREATE THE POSTGRESQL DATABASE
----------------------------------------

Only run the command for the database name used in backend/.env. For the default
example:

    psql -U postgres -c "CREATE DATABASE freight_forecasting;"

If PostgreSQL reports that the database already exists, that is fine.
If psql is not recognized, add the PostgreSQL bin directory to PATH or run psql
from the PostgreSQL installation folder.

Verify the connection using Python:

    .\.venv\Scripts\python.exe -c "import os; from pathlib import Path; from dotenv import load_dotenv; load_dotenv(Path('backend')/'.env'); import psycopg; url=os.environ['DATABASE_URL'].replace('+psycopg',''); print('DATABASE_URL:', url); conn=psycopg.connect(url); print('POSTGRES: connected'); conn.close()"

The .env value intentionally uses postgresql+psycopg:// because SQLAlchemy and
Alembic use that driver-qualified format. The direct psycopg smoke test removes
the +psycopg part before connecting.


STEP 6 - RUN DATABASE MIGRATIONS
--------------------------------

Run Alembic from the backend directory:

    Set-Location .\backend
    ..\.venv\Scripts\python.exe -m alembic upgrade head
    Set-Location ..

Expected result includes migration completion without an exception.

STEP 14 - TEST FRONTEND TO BACKEND TO MODEL
--------------------------------------------

Use the frontend manually in this order:

1. Open the app.
2. Navigate from splash/landing to Login.
3. Enter any values currently accepted by the demo login.
4. Open Forecast.
5. Press the forecast/analyze/refresh action.
6. Confirm the screen finishes loading and displays a prediction.
7. Open Optimizer.
8. Press its analyze/run action.
9. Confirm idle hours or a numeric prediction is displayed.
10. Open Risk.
11. Check whether a risk prediction action exists and whether it displays a result.
12. Return to the backend terminal and confirm request logs appeared.
13. Call the history endpoints from Step 10 and confirm new records exist.

A successful end-to-end path is:
frontend button -> services/api.ts -> FastAPI endpoint -> loaded pickle model ->
PostgreSQL history record -> JSON response -> frontend result.


STEP 15 - TEST FAILURE CASES
-----------------------------

Backend unavailable:
1. Stop the backend terminal with Ctrl+C.
2. Press a prediction button in the frontend.
3. Confirm the UI shows an error or remains recoverable instead of silently
   crashing.
4. Restart the backend and retry.

Invalid model or missing model:
1. Stop the backend.
2. Temporarily move one model file out of models (do not delete it).
3. Restart backend.
4. Call /api/health and verify the affected model is false and model_errors
   explains the issue.
5. Restore the file and restart backend.

Database unavailable:
1. Stop PostgreSQL or temporarily use an invalid DATABASE_URL.
2. Restart backend.
3. Confirm /api/health still responds.
4. Confirm prediction endpoints report database/history failure rather than a
   successful stored prediction.
5. Restore DATABASE_URL and PostgreSQL.

Frontend wrong URL:
- Browser: localhost/127.0.0.1 is usually correct.
- Android emulator: use 10.0.2.2.
- Physical device: use the computer LAN IP and allow port 8000 through Windows
  Firewall if required.

[ ] All three model files exist.
[ ] Model registry loads forecast, vessel, and risk without errors.
[ ] PostgreSQL connection succeeds.
[ ] Alembic migrations complete.
[ ] /api/health returns status ok and all models true.
[ ] test_api.py returns successful responses for all three predictions.
[ ] Prediction history endpoints contain records.
[ ] npm install completes.
[ ] npm run lint completes.
[ ] npx tsc --noEmit completes.
[ ] Expo frontend opens in web/emulator/device.
[ ] Frontend forecast action reaches the backend and displays a result.
[ ] Frontend optimizer action reaches the backend and displays a result.
[ ] Frontend risk action reaches the backend and displays a result, if the
